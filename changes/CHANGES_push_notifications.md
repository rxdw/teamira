# Push-уведомления (аудит 4.4.1)

Полная реализация с нуля — backend, миграция, 4 живых триггера, скрипт
для двух запланированных пушей, и мобильный клиент (Firebase, экран
настроек, deep-link по тапу). Пошаговая настройка реального Firebase-
проекта — в `docs/push_notifications_setup.md`; здесь про то, что уже
сделано и как это проверено.

## Backend — проверено 410 тестами на настоящем Postgres 16

**Инфраструктура**
- Миграция `8d82a0fd511d`: `push_tokens` (токен устройства + IANA-
  таймзона, репортится клиентом), `push_log` (для дебага и защиты от
  повторной отправки), `users.notification_prefs` (JSON, opt-out —
  отсутствующий ключ значит «включено»).
- `app/push.py` — сервис на Firebase Cloud Messaging. Безопасно
  отключён без `FIREBASE_CREDENTIALS_JSON` (тот же паттерн, что у
  Sentry и S3-хранилища аватарок), чистит протухшие токены по
  `UnregisteredError` (не трогает остальные ошибки — они могут быть
  временными), логирует каждую отправку.
- `app/routers/push.py` — регистрация/удаление токена (идемпотентный
  upsert по токену — важно для общих устройств, см. докстринг), чтение
  и изменение настроек по категориям.

**4 живых триггера, все через `BackgroundTasks` строго после
`db.commit()`** (не раньше — пуш про то, что откатилось транзакцией,
хуже, чем отсутствие пуша):
1. **Совпадение** (`co_view_vote.py`) — оба партнёра выбрали один тайтл.
2. **Партнёрская связь принята** (`partner.py`).
3. **Активность друга** (`diary.py::log_entry`) — только из
   интерактивного эндпоинта логирования, никогда из `log_watched`'s
   остальных вызовов (импорт CSV, Jellyfin-вебхук, co-view «посмотрено»)
   — импорт двухлетней истории Letterboxd не должен разослать друзьям
   двести уведомлений. Уважает `privacy_watched` через уже
   существующий `visible_to_friend`.
4. **Левел-ап** (`diary.py::log_entry`) — сравнение уровня до/после в
   одном запросе (уровень — не счётчик, а вычисляемое значение, см.
   `profile.py::compute_level_for_user`).

**Скрипт `scripts/send_scheduled_push.py`** (крон, не встроенный
планировщик — тот же принцип, что у `purge_deleted_accounts.py`):
- **Стрик на грани** — по локальной таймзоне устройства (не по
  фиксированному UTC-часу), только если серия ≥2 дней и сегодня ещё
  ничего не залогировано.
- **«N лет назад сегодня»** — с грамматически верным русским
  (год/года/лет, включая исключение 11-14).
- Обе защищены от повторной отправки в тот же день через `push_log`.
- Реально прогнан вручную (не просто написан): создавал тестовые
  данные, проверял оба сценария в режиме `--dry-run` и в реальном
  (с замоканным Firebase) — включая повторный запуск, подтверждающий
  отсутствие дублей.

**Вынесено и переиспользовано**: `app/streaks.py::current_streak` —
тот же алгоритм, что раньше был только внутри `profile.py`'s Wrapped-
статистики (там был непротестирован), теперь общий для чтения и для
триггера напоминания, с 10 новыми тестами.

**Найдено и исправлено по пути** (не относится напрямую к push, но
вскрылось при работе над ним):
- `scripts/purge_deleted_accounts.py` — пропущенный `datetime.utcnow()`
  в dry-run-ветке; моя прошлая работа над 3.4.1 не заглядывала в
  `scripts/`.
- Смысловая ошибка в собственном же черновике: рейтинг в дневнике —
  шкала 1-10, а не 1-5 (проверил по `widgets/heart_rating.dart`'s
  комментарию «9/10 выглядит теплее чем 3/10»), порог для «стоит
  взглянуть» в уведомлении был подобран неверно и исправлен.
- `NameError` в собственном же коде: переменные для пуша о совпадении
  были объявлены только внутри `if payload.decision`, что уронило бы
  запрос при голосе «нет».

## Mobile — не прогонялось через компилятор (в среде разработки никогда
не было Flutter SDK — см. ограничение во всех предыдущих CHANGES-файлах
этого проекта), проверено вручную: баланс скобок и разрешение всех
импортов по каждому новому/изменённому файлу, построчное чтение.

- `pubspec.yaml`: `firebase_core`, `firebase_messaging`,
  `flutter_local_notifications` (для показа уведомлений на переднем
  плане — FCM никогда не делает это сам, ни на Android, ни на iOS),
  `flutter_timezone` (единственный способ узнать настоящее IANA-имя
  таймзоны устройства, не сокращение вроде "MSK").
- `services/push_service.dart` — тонкая обёртка над API (по образцу
  остальных `*_service.dart`).
- `services/push_notification_manager.dart` — Firebase, разрешения,
  показ уведомлений на переднем плане, deep-link по тапу на
  `TitleDetailScreen` для совпадения/активности друга/воспоминания.
  **Безопасно деградирует**: `Firebase.initializeApp()` обёрнут в
  try/catch — без настоящего Firebase-проекта (см. ниже) приложение не
  падает, просто пуши не работают.
- `screens/profile/notification_settings_screen.dart` — новый экран,
  один пункт добавлен в `settings_screen.dart`. Рендерит категории с
  сервера (не хардкодит список) — новая категория позже не потребует
  релиза клиента. Оптимистичное переключение с откатом при ошибке.
- `state/app_state.dart` — `push.init()` при старте (регистрирует
  Firebase-слушатели независимо от статуса входа), `registerDeviceToken()`
  при login/register/bootstrap, `unregisterDeviceToken()` при logout.
- `navigation.dart` (новый файл) — глобальный `rootNavigatorKey`.
  Специально вынесен в отдельный файл, а не объявлен прямо в
  `app.dart`: `state/app_state.dart` тоже должен на него ссылаться, а
  `app.dart` уже импортирует `app_state.dart` — прямая ссылка друг на
  друга получилась бы циклическим импортом.

**Нативная конфигурация**
- Android: плагин `com.google.gms.google-services` подключён **условно**
  — только если `google-services.json` реально существует. Это не
  перестраховка ради перестраховки: без условия плагин **роняет саму
  сборку** («File google-services.json is missing») у всех, у кого
  Firebase ещё не настроен, а не только отключает push в рантайме — я
  сам сначала написал безусловное применение и заметил это только на
  повторной проверке собственного диффа. `POST_NOTIFICATIONS`
  (обязательно для Android 13+) и `default_notification_channel_id`
  добавлены в `AndroidManifest.xml`.
- iOS: `UIBackgroundModes: [remote-notification]` добавлен в
  `Info.plist`. Entitlements-файл и capability «Push Notifications» в
  Xcode — **не тронуто текстовым редактированием**: `project.pbxproj`
  достаточно хрупкий формат, чтобы правка вручную без возможности
  собрать проект была неоправданным риском. Это единственный шаг,
  оставленный полностью на `docs/push_notifications_setup.md`.

## Что специально не сделано в этом заходе

- Локализация копирайтинга пушей и нового экрана настроек — только
  русский, `.tr()` не использовался (см. `docs/push_notifications_setup.md`
  для обоснования — тот же выбор, что и в предыдущем апдейте
  онбординга/сторов).
- Deep-link для «партнёрская связь», «левел-ап», «напоминание о серии» —
  просто возврат на корень навигации, без экрана-назначения (нет
  очевидного кандидата в текущей навигации).
- Реальный Firebase-проект, APNs-ключ, `google-services.json`/
  `GoogleService-Info.plist` — не могу создать без настоящего
  Google/Apple Developer аккаунта. Весь код готов принять их в любой
  момент без дополнительных изменений.
