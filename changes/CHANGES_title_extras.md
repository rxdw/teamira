# Богатая карточка тайтла: игры, книги, манга, аниме

Карточка тайтла для не-фильмов была «пустой»: постер, жанры, пара строк и описание.
Теперь backend отдаёт в `GET /media/detail` вложенный объект `item.extras`, а на экране
тайтла появились секции под каждый тип. Остальные поля `MediaItem` не менялись.

## Что появилось

**Игры** — галерея скриншотов (полноэкранный просмотр), трейлеры (IGDB `videos` → уже
существующая секция трейлеров + кнопка play в шапке), «если понравилось» (IGDB
`similar_games`), языки (есть ли русский: интерфейс / субтитры / озвучка), время
прохождения, цена и скидка, Metacritic, достижения, поддержка геймпада (Steam), темы и
вид от лица, сюжет, «где играть» (Steam/GOG/Epic/…), серия, DLC, ремейки.

**Книги** — издатель, ISBN, страницы, язык, дата (раньше блок фактов у книг был пустым:
`_normalize` их не заполнял), время чтения, автор с био и фото (Open Library, по тапу),
«ещё от автора», сколько человек хотят прочитать / читают / прочли, первая строка,
ссылки «читать фрагмент» / «купить».

**Манга** — авторы (сюжет / рисунок) с фото, персонажи, теги с весом (AniList),
популярность, баннер AniList как фон карточки, «есть аниме-адаптация» (переход в карточку
аниме), продолжения и приквелы, «похожая манга», легальные ссылки «где читать», даты выхода.

**Аниме** — студия, серии (и «3 / 12», когда выходит), длительность, дата следующей серии,
первоисточник, ключевой staff, персонажи, темы, связи (оригинальная манга, сиквелы).

## Backend

- `schemas.py` — `TitleExtras` и вложенные модели; `MediaItem.extras`.
- `adapters/steam_store.py` + `game_store.py` — магазин Steam отдельным слоем с TTL 3 дня
  (цена не должна жить в вечном кэше).
- `adapters/igdb.py` — `full_detail_bundle` (карточка + трейлеры + похожие), расширенный
  запрос, `game_time_to_beats`; если расширенный запрос отклонён — отдаётся обычная карточка.
- `adapters/shikimori.py` — `roles` / `related` / `similar` для манги и аниме.
- `adapters/anilist.py` + `manga_reviews.get_info` — «паспорт» тайтла **отдельным** запросом
  и отдельной строкой кэша, чтобы он не мог сломать уже работающие отзывы.
- `adapters/google_books.py` — детали книги и «ещё от автора».
- `adapters/open_library.py` + `book_extras.py` — био автора и счётчики читателей. Био
  принимается только при совпадении названия И автора (чужая биография хуже отсутствия).
- `extras_merge.py` — чистые функции слияния обновляемых источников в `extras`.
- `routers/media.py` — оверлеи после кэша, параллельно, каждый с таймаутом.

### Кэш
Ключи не менялись (`diary.py` и `calendar.py` читают те же строки). Вместо этого карточка
без `extras` (кэшированная до этого релиза) или с `extras.complete == false` (Shikimori был
недоступен) пересобирается при следующем открытии. Цена, Metacritic, автор/читатели,
паспорт AniList в вечный кэш **не** попадают. Для аниме ключ кэша дополнения Shikimori
поднят до `shikimori-supplement-anime-v2`.

# Дополнение: трекер томов/глав/страниц и «Steam-extras»

## Трекер чтения (книги и манга)

Закладка «где я сейчас»: **том 7 из 42**, глава, страница. Карточка в стиле трекера сезонов
(бумажная, с мягкой тенью и «линованным» прогресс-баром), на скине clay счётчики — «вдавленные
лунки» с круглыми кнопками − / +.

- Манга: два счётчика (том и глава), книга: страница + быстрые «+10 / +25 / +50».
- Тап по числу — точный ввод (нижний лист с цифровой клавиатурой).
- Для книги — «≈ 3 ч 20 мин до конца» по уже рассчитанному времени чтения.
- Когда дошли до конца (последний том / последняя страница) — спокойная плашка и
  **предложение** записать в дневник. Сам трекер ни дневник, ни полку не трогает: перенос
  закладки — не запись вечера, а правила искренности привязаны именно к ним.
- Онгоинг без известного числа томов «конца» не имеет — плашка не появляется.
- «Сбросить прогресс» с кнопкой «отменить».
- Сохранение оптимистичное, с задержкой 0,5 с; на сервер уходит всё состояние целиком
  (идемпотентно), при выходе с экрана недосохранённое досылается.

Backend: таблица `reading_progress` (одна строка на пользователя и тайтл, без «итогов» — они
в каталоге), миграция `a5c2e7d19b36`, `GET/PUT /progress/reading`, попадает в экспорт данных
аккаунта и удаляется каскадом. Принимаются только `google_books`, `open_library`,
`shikimori_manga`; ноль = «не отслеживаю»; пустая закладка удаляется.

## Системные требования и Steam Deck

- Минимальные и рекомендуемые требования (переключатель-«табы»), метки на русском, платформы
  (Windows / macOS / Linux).
- Совместимость со Steam Deck: Verified / Playable / Unsupported — чип в «быстрых фактах» и
  строка с пояснением над требованиями. Источник — отдельный неофициальный эндпоинт Valve;
  его сбой не мешает остальным данным магазина.
- Ключ кэша магазина поднят до `steam:store:v2:…`, чтобы старые строки без новых полей не
  жили ещё 3 дня.

# Дополнение 4: серверные тексты — push, ошибки, iOS-разрешения

## 1. Push-уведомления на языке устройства
Раньше все ~35 шаблонов были только по-русски. Теперь каждый push пишется на обоих языках, а
получает его то устройство, на чьём языке он нужен.

- `backend/app/bi.py` — `Bi(ru, en)`: `str` со значением «по-русски» и `.en` рядом. Всё, что считает
  push строкой (PushLog, сравнения, тесты), работает как раньше; английский берёт только
  `PushService.send_to_user`.
- `push_tokens.locale` (`"ru" | "en"`, миграция `b8d4f1a6c3e7`). Токены без языка (старые установки) —
  русский, то есть ровно то, что они получали всегда. `POST /push/tokens` принимает необязательное
  поле `locale`.
- `send_to_user` группирует токены по языку: один человек с двумя устройствами на разных языках
  получает каждое на своём. В лог пишется русский текст (по нему идёт проверка «уже отправляли сегодня»).
- Переведены: `push.py` (совпадения, друзья, партнёр, уровни, ставки, альбом, капсулы, комнаты,
  рецензии), копии подписки и триала (`subscription.py`, `trial.py`), рассылки
  `send_scheduled_push.py` (серия, воспоминания, капсулы, годовщины) и `send_new_episode_push.py`.
  В английских вариантах названия берутся из `title_en`.
- Клиент: `registerToken(locale:)`, а при смене языка в настройках — `PushNotificationManager.refreshLanguage()`
  (молча переотправляет токен, разрешение не запрашивает).
- Названия и описания категорий на экране «уведомления» приходят с сервера по-русски и теперь переводятся
  на клиенте (`.toLowerCase().tr` — сервер пишет с заглавной, пары в ARB строчные).

## 2. Сообщения об ошибках с сервера
192 статических сообщения (≈125 английских показывались русскоязычным, ≈67 русских — англоязычным).
- `mobile/lib/services/server_messages.dart::translateServerMessage` вызывается в `ApiClient._decode`:
  фиксированные сообщения ищутся целиком (в ARB добавлено 170 пар `err…`), сообщения с именем или числом —
  по шаблонам (`слишком длинно — не больше N символов`, `<имя> is already in your circle` и т. п.).
  Неизвестное сообщение возвращается как есть. Сервер остаётся одноязычным.
- Не переводились: служебные сообщения для разработчика (`media_type must be …`, `Unrecognized media_id
  format`, `upstream error`) и сообщения, которые целиком приходят из `str(exc)` внутренних модулей.

## 3. iOS: тексты запросов разрешений
Камера была только по-английски, микрофон только по-русски. Добавлены `ios/Runner/en.lproj/InfoPlist.strings`,

# Исправление: карточки, которые «перестали открываться» из-за пересборки кэша

Карточка игры/книги/манги, закэшированная до появления `extras`, считается устаревшей и пересобирается
при следующем открытии. Если источник в этот момент недоступен (Google Books отвечает 429, IGDB лежит),
пересборка возвращала `None` → «Title not found», хотя раньше карточка открывалась из кэша.
Теперь `media_detail` запоминает старую копию (`stale_copy`) и при неудачной пересборке отдаёт её (с оверлеями),
а пересборка повторится при следующем открытии.
