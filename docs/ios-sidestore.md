# iPhone: как обновить приложение (SideStore)

Рабочая шпаргалка. Полный разбор с пояснениями — в плане запуска, фаза **2.13.4.2**.

## Главное

Адрес сервера вшивается в приложение при сборке (`--dart-define=SEENLY_API_BASE_URL=...`). Поэтому, когда бэкенд заработал на домене, **старая сборка на телефоне на него не перейдёт**: нужна новая сборка с новым адресом, поставленная поверх старой.

Сборка под iOS возможна только на macOS. У вас Windows, поэтому `.ipa` собирается в **Codemagic** (он у вас уже настроен). Отдельных файлов в проекте для этого не нужно.

## Обновление за шесть шагов

1. **Код должен быть в репозитории.** Codemagic собирает то, что лежит в репозитории (у вас `origin` — GitHub, `rxdw/teamira`), а не то, что на вашем компьютере: закоммитьте и запушьте изменения в ту ветку, которую собираете. Не запушено — соберётся старый код.
2. **Переменные в Codemagic** (приложение → Environment variables):
   - `SEENLY_API_BASE_URL` = `https://ваш-домен.ru` (без `/` в конце);
   - `SEENLY_APP_VERSION` = `0.1.0`. Для собственных запусков — `0.1.0-own`: сборка `--release` всегда помечается в аналитике как `release`, и по этой метке свои запуски отличаются от чужих. Это метка для аналитики, в `--build-name` её подставлять нельзя: версия приложения в iOS должна быть числовой.
3. **Аргументы сборки iOS** (поле Build arguments в Workflow Editor или строка `flutter build ios ...` в скрипте `codemagic.yaml`):
   ```
   --dart-define=SEENLY_API_BASE_URL=$SEENLY_API_BASE_URL --dart-define=SEENLY_APP_VERSION=$SEENLY_APP_VERSION --build-number=$BUILD_NUMBER
   ```
   `$BUILD_NUMBER` — встроенная переменная Codemagic, растёт на единицу с каждой сборкой; растущий номер нужен, чтобы SideStore видел обновление.
4. **Запустить сборку** (Start new build, нужная ветка) и скачать `.ipa` из артефактов. Стоимость: 500 бесплатных минут в месяц на macOS M2 для личного аккаунта (для командного бесплатных минут нет).
5. **Поставить на телефон поверх старой:** передать файл (Telegram «Избранное», iCloud Drive), в «Файлах» нажать на `.ipa` → Поделиться → SideStore (или SideStore → My Apps → «+»). Тот же Apple ID, что при первой установке; старую сборку заранее не удалять.
6. **Войти заново.** Аккаунты и записи домашнего бэкенда на боевом сервере не существуют, а старый токен боевой сервер не примет: зарегистрируйтесь заново. Проверка: запись в дневник → свернуть приложение → `docker compose exec api python -m scripts.analytics_report --days 1`.

## Если телефонов несколько или обновлений много: свой источник SideStore

```bash
python3 mobile/tools/ios/make_altstore_source.py Seenly-0.1.0-3.ipa \
  --ipa-url https://ваш-домен.ru/ios/Seenly-0.1.0-3.ipa \
  --source site/ios/source.json \
  --notes "Что нового"
```

Скрипт читает версию, номер сборки, минимальную iOS и разрешения прямо из `.ipa`, кладёт новую версию **первой** в `source.json` (SideStore ищет обновление по первой записи, не по дате) и отказывается, если номер сборки не поднят. Выложите `source.json` и `.ipa` в `/home/deploy/site/ios/`; в SideStore один раз: Sources → «+» → `https://ваш-домен.ru/ios/source.json`.

Тесты скрипта: `cd mobile && python3 -m unittest discover -s tools/ios`.

## Ошибка «requires a selected Development Team» в Codemagic

Сборка проходит («Xcode build done»), а потом падает с «Building a deployable iOS app requires a selected Development Team with a Provisioning Profile». Это не ошибка кода: Codemagic собирает под устройство как для App Store и требует подпись, а для SideStore она не нужна (приложение подписывает сам SideStore). Решение — собирать с флагом `--no-codesign` и упаковывать `.ipa` вручную; готовый workflow лежит в `codemagic.yaml` в корне репозитория (подключается в настройках приложения: способ настройки «codemagic.yaml»). В нём уже стоит адрес домашнего сервера `http://192.168.1.33:8000` (работает только в вашей Wi-Fi сети); когда бэкенд переедет на домен, замените `SEENLY_API_BASE_URL`.

## Ограничения бесплатного Apple ID

- не больше трёх активных приложений;
- подпись живёт 7 дней, SideStore обновляет её в фоне; если не успел — «Refresh» в SideStore (к серверу это не относится);
- нет Universal Links и push-уведомлений;
- для раздачи тестерам SideStore не подходит (у каждого свой Apple ID и файл сопряжения); для чужих iPhone нужен TestFlight (платный аккаунт).

## Что не проверено

Скрипт источника писался без Mac и без живого SideStore: проверен тестами на искусственных `.ipa`. Настройку Codemagic я не видел (в проекте нет `codemagic.yaml`, значит она живёт в интерфейсе Codemagic), поэтому шаги 2–3 описаны общим образом: если у вас там уже свои аргументы сборки, добавьте к ним только эти три.
