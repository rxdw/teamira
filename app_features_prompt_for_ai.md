# Seenly — app feature summary for AI

Ниже — готовый текст для ChatGPT / Copilot / любого ИИ, чтобы он понял, что это за приложение, какие у него функции, какие сценарии важно поддержать, и как он должен мыслить при генерации новых экранов, фич или UX.

---

## Что это за приложение
Seenly — это мобильное приложение для персонального дневника по медиа: фильмы, сериалы, игры, аниме, книги, манга. Главное — не просто хранить список просмотренного, а делать это в личном, уютном формате: дневник, заметки, оценки, воспоминания и история по каждому медиа-объекту.

Это не просто трекер "посмотрел/не посмотрел". Это приложение про личное впечатление и архив: "что я смотрел, что понравилось, что стоит пересмотреть, что было в тот вечер".

---

## Ключевая идея продукта
- Люди ведут личный архиваж вещей, которые смотрят и читают.
- У пользователя есть ощущение вечернего ритуала: "я сегодня смотрел, я оценил, я записал впечатление".
- Приложение должно выглядеть как cozy journal, а не как унылый dashboard.
- Основное настроение: warm paper, личная память, уют, редакторский стиль, малое число акцентов.

## Крутые функции (основные фишки)

### 1. Дневник по медиаконтенту
- Пользователь может логировать просмотренное/прочитанное/сыгранное.
- У каждого элемента есть дата, оценка, заметка, статус, тип медиа.
- Приложение хранит историю по каждому объекту.
- На странице объекта можно видеть timeline: "в какие вечера ты это видел/читал".
- Есть концепция rewatch timeline и “ваши вечера с этим заголовком”.

### 2. Личная память и серия вечерних событий
- Это не просто библиография; это история впечатлений.
- Пользователь может возвращаться к прошлым вечерам и смотреть, что он воспринимал в тот момент.
- Подход: "дневник о культуре" + "личный архив".

### 3. Рейтинг и оценка по ощущениям
- Есть оценка по шкале от 1 до 10.
- Оценка визуально окрашивается теплыми цветами, а не выглядит как сухой числовой рейтинг.
- Пользователь может оценивать не только статус, но и эмоциональную окраску опыта.

### 4. Collections / shelves / editorial feeds
- Пользователь видит подборки и shelves, которые похожи на рекомендательные разделы.
- Разделы могут быть editorial / curated / personal / themed.
- Это позволяет приложению чувствовать себя не просто списком, а живым каталогом культуры.

### 5. Search + title detail page
- Поиск контента по названию.
- Детальная страница элемента содержит: описание, статус, рейтинг, жанры, актёров, похожие заголовки.
- Для сериалов/фильмов/аниме это может идти через TMDB-подобные источники.
- На странице есть и личная история пользователя, и публичная информация о контенте.

### 6. Ask Teamira / AI-помощник
- Есть AI-ассистент для вопросов по контенту, рекомендациям и “что посмотреть сегодня”.
- Он работает как умный интерфейс поверх пользовательского архива и рекомендаций.
- Это помогает приложению перейти от passive tracker к active assistant.

### 7. Автотрекинг через сторонние источники
- App может автоматически понимать, что пользователь досмотрел/дослушал/доиграл что-то со сторонних платформ.
- Есть поддержка Plex, Jellyfin, Kodi, браузерного расширения, и отдельных источников вроде YouTube/Twitch/streaming-платформ.
- Это делает продукт “сильнее”, чем обычный ручной дневник.

### 8. Browser extension / web integration
- Есть расширение для браузера, которое умеет отслеживать просмотр контента на сервисах.
- Это позволяет собирать события даже без отдельного API от сервиса.
- Это одна из самых сильных фишек продукта.

### 9. Where to watch / watch providers
- Пользователь может видеть, где смотреть тот или иной контент.
- Есть партнерские ссылки и трафик на сервисы.
- Это не просто каталог, а коммерческая логика вокруг “сервисов, где смотреть”.

### 10. Social / friends / co-watching
- В приложении есть механика друзей, активности, совместного просмотра, “watch together”.
- Есть области с activities feed, friends, social loops.
- Это делает продукт более живым и community-oriented.

## Важные, но не “крутые” функции

### 1. Авторизация и учетная запись
- Login / register / sign in / sign out.
- У пользователя есть учетная запись, а state связан с auth.
- Важны правильные сценарии “вошёл / вышел / onboarding / home”.

### 2. Настройки пользователя
- Темы, локализация, настройки карты, скрытие spoilers, включение/выключение rabbit mascot, etc.
- Это кажется мелочью, но создает ощущение качественного продукта.

### 3. Локальные preferences
- Настройки не всегда привязаны к серверу.
- Для многих вещей используются device-local preferences.
- Это значит, интерфейс должен поддерживать идею “локальных пользовательских настроек, не всегда аккаунтных”.

### 4. Collections, shelf grids, profile tabs
- У каждого раздела есть собственный набор карточек и состояний.
- Секции: home, diary, collections, profile, friends, settings.
- Это важный part of UX — большое количество разноплановых экранов.

### 5. Caching и подгрузка данных
- Приложение не всегда перезагружает всё заново.
- Есть ленивые загрузки и кэширование на уровне экрана / сервисов.
- Это должно быть в части DX и архитектуры будущей генерации.

### 6. Account-scoped local state
- Некоторые данные привязаны не просто к устройству, а к конкретному пользователю.
- То есть важна гибридная система: device-local settings + user-scoped state.

## Основные сценарии использования

### Сценарий 1. Я хочу зафиксировать вечер
- Пользователь открывает приложение.
- Находит фильм/сериал/книгу.
- Добавляет запись в дневник.
- Указывает оценку, дату и заметку.
- Элемент появляется в истории и на timeline.

### Сценарий 2. Я хочу вспомнить, что смотрел раньше
- Пользователь открывает свой профиль или дневник.
- Видит архив по датам.
- Переходит к конкретному элементу и видит историю его появления.

### Сценарий 3. Я хочу получить рекомендацию
- Пользователь открывает Ask Teamira или recommendations section.
- Приложение рекомендует фильмы/сериалы/книги на основе истории и предпочтений.

### Сценарий 4. Я хочу, чтобы приложение автоматически отслеживало контент
- Пользователь подключает Plex, Jellyfin, Kodi или browser extension.
- При просмотре/прослушивании система пишет в дневник автоматически.

### Сценарий 5. Я хочу найти, где смотреть
- Пользователь открывает title detail.
- Видит провайдеров и ссылки, где можно смотреть.
- Нажимает и переходит через referral / affiliate flow.

## UX / visual principles
- Warm paper background
- Soft borders and subtle shadows
- Great typography
- No cold corporate dashboard vibe
- “Personal archive, not social network”
- Editorial, calm, intimate UI
- The app feels like a diary, not a SaaS backend

## Короткий промпт для ИИ

"Сделай приложение как cozy personal media diary / journal. Это приложение для отслеживания фильмов, сериалов, игр, аниме, книг и манги. Оно должно позволять пользователю вести дневник, ставить оценки, писать заметки, видеть историю по каждому заголовку, смотреть коллекции, искать контент, получать рекомендации и видеть, где смотреть в данный момент. Добавь функции: auth, profile, diary timeline, media detail page, home feed, collections, friends, co-viewing, auto-tracking via Plex/Jellyfin/Kodi/browser extension, AI assistant Ask Teamira, local settings, watch providers, referral links. Приложение должно ощущаться как теплый бумажный журнал, а не как холодный аналитический dashboard. Поддерживай тёплую палитру: бумажно-бежевый фон, тёмный коричнево-чернильный текст, один главный акцент plum, категориальные цвета для фильмов/сериалов/игр/аниме/книг. Сохраняй уютную, личную, редакторскую эстетику, мягкие тени, скруглённые карточки и аккуратную типографику."

## Итог
Это приложение — смесь из:
- дневника
- трекера
- коллекционного каталога
- recommendation engine
- social layer
- auto-tracking system
- watch-provider platform
- AI-помощника

Именно это сочетание делает его сильным, уникальным и “живым”, а не просто списком watched/unwatched.
